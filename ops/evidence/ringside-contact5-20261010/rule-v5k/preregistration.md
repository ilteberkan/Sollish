# Rule v5k pre-registration (10 Oct 2026)

Written before any v5k checkpoint was trained or evaluated. Nothing below is changed after a test-seed result is seen.

## What changes
Contact 5 gets four kicks and a knee (`teep`, `lowKick`, `bodyKick`, `headKick`, `knee`; table `combat-v5-strikes.ts`), kick rules in
`combat-v5.ts` (`V5_KICK_RULES`: kicks are single blows, a missed kick opens a counter window, a knee can end a clinch, a low kick never
stuns or knocks down), 5 more learner actions and 6 more observable inputs (`contact-learner.ts`). The in-match learning rule is unchanged
(actor 1, critic 0.05, fast 2, fastInputs 0, entropy 0.03). The readout changes shape, so every checkpoint is trained from zero weights.
The engine id is regenerated by `freeze.ts` from the checkpoint, the strike table, the kick rules and the rest of the identity.

## Hypotheses
- H1 (primary): with the same frozen checkpoint, in-match learning beats its non-learning copy against learned held-out opponents.
  Metric: point margin of the learner minus its opponent, learning arm minus frozen arm, paired by seed, side and opponent.
- H2 (secondary): the same comparison against the scripted held-out styles (`switcher`, `bodySnatcher`, `slipper`, `mover`; they kick too).
- H3 (secondary): learning from the trained checkpoint beats learning from zero weights (`untrainedLearning`), same pairing.
- H4 (descriptive, no claim unless the interval is above 0): MaleCNS reservoir vs the shuffled-graph control.

## Primary criterion
H1 is claimed only if the paired bootstrap 95% interval (2000 resamples, fixed resampling seed 99, as in `eval.ts`) of
(learning - frozen) margin, pooled over the learned opponents (`mirrorFrozen`, `rule-v5k/heldout-a`, `rule-v5k/heldout-b`), has a lower bound above 0.
No hyperparameter is selected on these results. If H1 fails, product text says in-match learning is not shown for v5k.
H2 and H3 are reported per opponent and pooled with the same interval; they do not gate the claim.

## Data
- Test seeds: `test6:<opponent>:<0..199>` (new set, registered in `common.ts`, never used before), 200 bouts per arm and opponent, sides alternating.
- Lifetime training (tags `v5kmain`, `v5kheldoutA`, `v5kheldoutB`), the held-out learned opponents use other rates than the main checkpoint:
  main and shuffled-control 12000 rounds (actor 0.1, critic 0.05, fast 0.5, entropy 0.1); heldout-a 6000 rounds (0.2, 0.1, 1, 0.05); heldout-b 6000 rounds (0.05, 0.025, 0, 0.15).
- Training pool: `TRAIN` scripts + self; `HELD_OUT` styles never appear in training. Scripted styles were rewritten for v5k to use kicks and knees.
- Probe seeds and tags (`probe*`, `smoke*`) may be used before the run to debug the pipeline and to set the strike numbers; the engine hash at the
  start of the full run is recorded with the results and not changed afterwards.

## Balance band (live engine, both corners learning, fallback plans, `balance:0..299`)
Either side wins 40-60 % (draws count half), 40-65 strikes per round, kicks and knees 15-35 % of strikes, knockdowns in 15-35 % of rounds, every
punch, kick and the knee used at least once. A miss does not change the test; it is reported and the product ships only if it is fixed with a new engine id.

## Limits
Scripted opponents are not human fighters. Kick damage, reach and stamina numbers are game design, not measured kickboxing data. A passing H1 means the
learning rule helps against these opponents under these seeds, not that the connectome adds anything (H4) and not that it is a mind or a brain.
