# Devnet wallet SDK

Local transaction builders for the deployed-program candidate; no serialized transaction supplied by an API is accepted for signing. All entry points reject disabled configuration and non-devnet genesis. `tokenMint`, `stakingPoolId`, and `rewardPhaseId` are deployment configuration, not token launch instructions. Missing or unfunded accounts fail closed.

- `readStakingState(deployment, player, rpc?, commitment?)`: canonical pool/position, exact integer accrued reward quote, principal/reward reserves and chain timestamp. Default commitment is `finalized`. Pausing game admission does not disable withdrawals or claims.
- `readRewardState(deployment, player, epoch?, rpc?, commitment?)`: fixed funded phase and last completed UTC hour by default. Eligible volume determines the pro-rata hourly share. A missing participant receipt means “no current claim record”; it does not prove payment. Completed unsealed hours can be claimed: the first claim seals them.
- `prepareIncentive({ deployment, player, action, amount?, epoch? }, rpc?)`: only `stake`, `unstake`, `claim-staking`, `claim-wager`, `claim-hourly`. Amounts use bigint token base units, six decimals. The returned quote excludes network fees/rent and is a snapshot, not a guaranteed transfer amount. Staking accrual can advance before execution.
- `sendIncentive({ deployment, wallet, action, amount?, epoch?, onPrepared? }, rpc?)`: invokes the wallet once. Persist its JSON-safe public ticket in `onPrepared` before the wallet opens. Failure to persist aborts before signing. Returns `finalized` only after the landed message matches the locally constructed message. Refresh finalized balances/events to display amounts actually paid.
- `trackIncentive(deployment, ticket, signatureOrNull, rpc?)`: read-only `unknown`, `pending`, `failed`, or `finalized`. Reconstructs the entire permitted transaction from fixed deployment/account derivations and verifies the stored message. An absent signature remains unknown; a wallet bridge can fail after broadcast. Use wallet/explorer history to recover the signature. Do not blindly repeat a deposit, even after blockhash expiry. No balance-delta heuristic is treated as proof of this particular operation.
- `prepareCoinflip` / `sendCoinflip` preserve their unrewarded default. Passing explicit `rewardPhaseId` opts into atomic game admission + funded reward credit. `deployment.tokenMint` is then mandatory. The quote identifies the phase, UTC epoch and wager token amount. Exhausted rewards fail that rewarded admission; there is no silent downgrade to an unrewarded bet.

Wallet transfers target the signer's canonical ATA. Missing destination ATAs are created idempotently. The small builder follows the [official ATA interface](https://github.com/solana-program/associated-token-account/blob/main/interface/src/instruction.rs): discriminator `1` and six ordered accounts, tested explicitly. The SDK supports classic SPL Token and the contract's fail-closed Token-2022 subset: mint MetadataPointer/TokenMetadata, token account ImmutableOwner. Transfer fees, hooks, permanent delegates, mutable mint/freeze authority, frozen accounts and unsupported extensions are rejected. Existing delegated user token accounts are also rejected conservatively.

`src/schema.ts` is generated from the actual Anchor IDLs, including qualified nested account paths (`game.player`, `transfer.player`). Run `pnpm idl:sync` after building contracts; `pnpm idl:check` detects drift. Account-layout fixtures, canonical PDA/owner binding, principal/reserve failures, pro-rata math, explicit rewarded opt-in, recipient binding and submission uncertainty are covered by local client tests. These mocked RPC tests are not provider availability or devnet deployment evidence.

RPC trust remains explicit: genesis, program IDs, executable bits, account owners, seeds and data invariants are verified, but RPC account responses are not cryptographic state proofs. The SDK does **not** attest the deployed program bytecode/hash or upgrade authority. Production release requires independently verified deployment artifacts and upgrade governance; this package has no mainnet switch. Token/phase/pool funding and the real provider path must be validated before enabling their live UI configuration.
